# GoMessage 项目定位

## 一句话定位

GoMessage 是一个面向告警、Webhook 与任意结构化事件的消息转发系统，它负责把机器世界的原始信息，以更清楚、更稳定、更低成本的方式送到人类面前。

## 它不是什么

GoMessage 不是：

- 监控系统本身
- 日志系统本身
- 聊天软件本身
- 一个为了追热点而包装出来的 AI 壳子

它不试图取代这些系统，而是专注解决它们之间长期存在、却经常被重复开发的那一段：

`机器 -> 通知 -> 人类`

## 它是什么

GoMessage 是一个“机器向人类汇报”的中间层。

它负责：

- 接收上游系统推送的结构化事件
- 保留原始事实
- 对消息做必要的整理与渲染
- 将消息分发到不同的聊天客户端或通知通道
- 帮团队摆脱零散脚本、重复劳动和各家文档碎片化带来的复杂度

它的价值，不在于“多聪明”，而在于：

- 稳定
- 清楚
- 克制
- 可控
- 低重复劳动

## 它的初心

GoMessage 最初想解决的，不是“发消息”这件表面功能。

它真正关心的是：

- 自动化越来越多之后，人是否还跟得上机器世界的变化
- 当海量机器信息扑面而来时，人是否还能及时看到真正重要的东西
- 能否让机器主动、准确、友好地向人类汇报，而不是把人困在看不完的面板和日志里

所以 GoMessage 的初心从来都是：

**让机器世界更清楚、更自然地向人类汇报。**

这里所说的“自然”，并不意味着花哨，也不意味着替人做主。

它更接近一种克制而友好的方向：

- 尽量不增加人的额外负担
- 尽量不制造理解上的伤害
- 尽量把复杂留在系统内部，把清楚留给用户
- 尽量让事实以更平和、更可信的方式抵达人

## 它坚持的产品原则

### 1. 原始事实优先

GoMessage 可以渲染、整理、格式化消息，但不应该篡改原始事实。

专业用户有权看到原始信息，也应该始终能追溯到原始信息。

### 2. 清晰传达重于炫技表达

GoMessage 的目标不是让消息“更花”，而是让信息更清楚。

任何表达形式、模板设计或未来可能引入的 AI 辅助能力，都应服从于清晰传达，而不是喧宾夺主。

### 3. 减少重复劳动

不应该让每个团队、每个项目都重复写一遍脆弱的通知脚本。

GoMessage 的存在，本质上是在消灭这些低价值、高重复、难维护的琐事。

### 4. 不抢走人类判断

GoMessage 可以帮助机器更好地汇报，但不应该默认替人做决定。

它尊重人类判断，也尊重专业用户对原始信息的需求。

### 5. 克制比喧闹更重要

这个项目的气质不应该是“多说话”，而应该是“在该说的时候，把事实稳稳送到人面前”。

## 面向未来的延续

未来的软件世界会越来越自动化，AI 助手也会越来越普及。

但无论入口是聊天软件、自动化工作流，还是 AI 助手，GoMessage 真正可以长期坚持的位置仍然成立：

- 它可以是事件入口
- 可以是消息路由层
- 可以是渲染与分发层
- 也可以成为人类判断前的事实承接层

换句话说，时代会变，接口会变，交互方式也会变；  
但 GoMessage 仍然可以继续做同一件事：

**让机器世界向人类汇报这件事，变得更简单、更清楚、更值得信赖。**

## 为什么这个项目值得继续做

因为真实世界里仍然存在这些问题：

- 机器信息越来越多
- 告警链路越来越复杂
- 团队仍然在写大量重复通知脚本
- 原始 JSON 仍然很难直接被人使用
- 各类聊天客户端、消息协议和接入方式仍然零散分裂

这些问题并没有消失。

所以 GoMessage 也没有失去意义。

它不是一个为了短期新鲜感而存在的项目，而是一个愿意在真实系统世界里长期承重的项目。

## 最后一句话

GoMessage 的价值，不在于“替人类说话”，而在于：

**让机器终于学会好好向人类汇报。**
